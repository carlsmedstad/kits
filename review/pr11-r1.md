## r1-F1 | kits/kit-arch-development/files/arch-nvcheck:266 | must-fix

Claim: Ctrl-C discards completed worker results that the merge loop has not yet consumed, violating R11's guarantee that an interrupted run keeps every finished entry.

Because: Workers can finish faster than the consumer, which runs two jq processes and relays stderr for each entry. There is no interrupt handler that stops new work and drains completed entries before exiting; the EXIT trap removes their temporary files. I ran the unchanged script with the default four workers, 80 positional packages with old cached entries, a successful git stub, and a pkgctl stub returning a valid one-package JSON array immediately. The probe watched the final worker files under `tmp.*/entries/` (excluding `.tmp` and `.err`), then sent SIGINT to the process group once at least 12 had finished and at least four were awaiting persistence. At interruption, 12 entries were complete but only three were merged. After exit, nine of those completed packages still had their old `2020-01-01T00:00:00Z` entries. This is ordinary Ctrl-C, not SIGKILL or a failed check. Preserve completed entries through graceful interruption, including entries already queued while another entry is being merged.

Verified: **by running** `python /tmp/pr11-r1-probe.py` from the worktree root. The retained probe creates its own temporary cache and stubs, invokes `bash kits/kit-arch-development/files/arch-nvcheck` by absolute path, and uses `os.killpg(proc.pid, signal.SIGINT)`. ## r1-F2 | kits/kit-arch-development/files/arch-nvtodo:99 | must-fix

Claim: A split package's pkgbase incorrectly overrides a different package's matching `provides`, allowing a consumer and its out-of-date provider to appear in the same batch.

Because: `owner[$3] = base` registers both pkgnames and pkgbases as installable package names, and line 103 then refuses a provides mapping for any name already in `owner`. A split pkgbase need not be the name of any package it builds. This contradicts the specification's mapping of **pkgnames and provides** and breaks the dependency graph required by R6. Reproducing fixture:

```text
virtual/.SRCINFO:
pkgbase = virtual
pkgname = unrelated

real-provider/.SRCINFO:
pkgbase = real-provider
pkgname = real-provider
\tprovides = virtual

consumer/.SRCINFO:
pkgbase = consumer
\tdepends = virtual
pkgname = consumer
```

Here `\t` denotes a literal tab. The JSON todo set contains `consumer` and `real-provider`, both with versions `1` and `2` and `out_of_date: true`; `virtual` is not on the todo list. The actual output puts both in Batch 1 with no dependency annotation. The required output puts `real-provider` first and `consumer` in Batch 2. The real-package-name preference should apply only to actual pkgnames, not to split-package grouping names. This collision was not present in the current live cache, but the fixture is a valid dependency arrangement.

Verified: **by running** `python /tmp/pr11-r1-probe.py`, and its fixture can be rerun directly from the worktree root:

```sh
XDG_CACHE_HOME=/tmp/pr11-r1-05w2p0i8/split-provider \
  bash kits/kit-arch-development/files/arch-nvtodo --deps
```

## r1-F4 | kits/kit-arch-development/files/arch-nvtodo:146 | must-fix

Claim: Under a translated locale, cycle diagnostics include a nonexistent `-:` member and combine unrelated cycles into one purported cycle.

Because: The cycle report parser recognizes only the English `input contains a loop` separator, but `tsort` inherits the user's locale. With Swedish messages, the separator is `tsort: -: indata innehåller en slinga:`; it falls through to the member parser, which appends `$2` (`-:`). Subsequent separators never flush the report. With two disjoint cycles, `a <-> b` and `c <-> d`, English produced two correct warnings, while Swedish produced one warning: `arch-nvtodo: warning: -:, a, b, -:, c and d depend on each other, their order is arbitrary`. This fails the second-pass specification's one-line report naming each cycle's members. Force a stable locale for the parsed tsort diagnostics, or obtain cycle membership without parsing translated messages.

Verified: **by running** against both the live cache and an isolated two-cycle fixture. The live-cache command below prints `arch-nvtodo: warning: -:, python-filelock and python-hatchling depend on each other, their order is arbitrary`:

```sh
  bash kits/kit-arch-development/files/arch-nvtodo > /dev/null
```

The two-cycle fixture is retained and reproduces the combined warning with:
