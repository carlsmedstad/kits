## r1-F1 | kits/kit-arch-development/files/arch-nvcheck:172 | must-fix

Claim: When the candidate names exceed one `xargs` command buffer, the result file silently drops every checked package after the first invocation, contradicting R4.

Because: Line 162 permits `xargs` to invoke `pkgctl` multiple times, producing multiple JSON arrays; the stamping `jq` preserves that stream, but the merge reads only `$new[0]`. A positional run with 800 valid, 189-character package names exits 0 and saves only 689 entries. Previously saved entries for the remaining candidates are also excluded from `keep`, so the same defect can erase existing results. The following reproduction runs the actual script and actual `xargs`/`jq`, stubbing Git and upstream checking to avoid network traffic. The checker stub emits one array per invocation, matching the installed `pkgctl version check --json` behavior.

```sh
python - <<'PY'
import json, os, pathlib, subprocess, tempfile
script = str(pathlib.Path('kits/kit-arch-development/files/arch-nvcheck').resolve())
with tempfile.TemporaryDirectory(prefix='pr11-batching-') as root:
    root = pathlib.Path(root)
    cache = root / 'arch-nvcheck'
    cache.mkdir()
    bindir = root / 'bin'
    bindir.mkdir()
    stubs = {
        'git': '#!/bin/sh\nexit 0\n',
        'pkgctl': '#!/usr/bin/python\nimport sys,json\nprint(json.dumps([dict(pkgbase=p,status="success",out_of_date=False,local_version="1",upstream_version="1") for p in sys.argv[5:]]))\n',
    }
    for name, body in stubs.items():
        executable = bindir / name
        executable.write_text(body)
        executable.chmod(0o755)
    names = [f'pkg-{i:04d}-' + 'a' * 180 for i in range(800)]
    for name in names:
        (cache / name).mkdir()
    env = dict(os.environ, XDG_CACHE_HOME=str(root),
               PATH=str(bindir) + ':' + os.environ['PATH'])
    run = subprocess.run(['bash', script, *names], env=env,
                         text=True, capture_output=True)
    saved = json.loads((cache / f'check-{os.environ["USER"]}.json').read_text())
    print('exit', run.returncode, 'expected', len(names), 'actual', len(saved))
PY
```

## r1-F3 | kits/kit-arch-development/files/arch-nvtodo:80 | must-fix

Claim: A later cached package providing an earlier package's name overwrites its owner and can put a dependent in the same batch as its out-of-date dependency.

Because: `owner[name] = base` retains only the last definition, allowing an alternative provider to erase a concrete package-name mapping. With `alpha`, `consumer` depending on `alpha`, and a later `zeta` providing `alpha`, a todo set containing `alpha` and `consumer` puts both in Batch 1. The unchanged `zeta` clone alone changes the ordering of those two packages. R6 requires the dependency graph, and the specification requires a dependent's batch to follow its todo dependencies; concrete package identities must not disappear due to provider traversal order.

```sh
python - <<'PY'
import json, os, pathlib, subprocess, tempfile
script = str(pathlib.Path('kits/kit-arch-development/files/arch-nvtodo').resolve())
with tempfile.TemporaryDirectory(prefix='pr11-provider-') as root:
    cache = pathlib.Path(root) / 'arch-nvcheck'
    for name, extra in [('alpha', ''), ('consumer', '\tdepends = alpha\n'),
                        ('zeta', '\tprovides = alpha\n')]:
        clone = cache / name
        clone.mkdir(parents=True)
        (clone / '.SRCINFO').write_text(
            f'pkgbase = {name}\npkgname = {name}\n' + extra)
    run = subprocess.run(
        ['bash', script, '-'],
        input=json.dumps([{'pkgbase': n, 'out_of_date': True}
                          for n in ['alpha', 'consumer']]),
        env=dict(os.environ, XDG_CACHE_HOME=root, LC_ALL='C'),
        text=True, capture_output=True)
    print('exit', run.returncode, 'stdout', repr(run.stdout),
          'stderr', repr(run.stderr))
PY
```

Verified: by running the Python fixture above; observed exit 0, no stderr, and `Batch 1\n alpha\n consumer\n`. Preserve concrete package mappings when resolving alternative providers rather than using last-write-wins ownership.
